# 07 — Data Dictionary

## Document Scope

This document defines the logical data dictionary for Version 1 of the Unified Education Platform.

This is a logical data dictionary only. It does not define physical database schema, SQL, migrations, Laravel models, or implementation code. Attribute names and data types are logical and may be refined in later physical database design while preserving the business rules defined in the official source documents.

Source-of-truth documents:

- `AI_DOCS/00_Project_Context.md`
- `AI_DOCS/01_Project_Vision.md`
- `AI_DOCS/02_Software_Requirements.md`
- `AI_DOCS/03_System_Architecture.md`
- `AI_DOCS/06_Database_Design.md`

## Important Scope Clarification

Notifications are explicitly out of scope for Version 1. Therefore, **Notification is not defined as a Version 1 data entity** in this dictionary. This preserves the Project Context rule that push notifications, email notifications, and SMS notifications are outside Version 1 scope.

# 1. User

## Entity Name

User

## Description

Represents a global authenticated identity used to access the Platform.

## Purpose

To provide a single identity foundation for Super Admin, Teacher, Teacher Staff, Student, and Parent role contexts.

## Attributes

| Attribute | Data Type | Required / Optional | Default Value | Validation Rules |
|---|---|---|---|---|
| User Identifier | Identifier | Required | Generated by system | Must be unique. |
| Display Name | Text | Required | None | Must be valid human-readable text. |
| Login Identifier | Text | Required | None | Must be unique according to authentication rules. |
| Authentication Secret | Secret | Required | None | Must be stored securely; never exposed in readable form. |
| Account Status | Status | Required | Active | Must represent an allowed account state. |
| Created At | DateTime | Required | Current server time | Must be system-generated. |
| Updated At | DateTime | Optional | None | Updated when account metadata changes. |
| Archived State | Archive State | Required | Active | Must follow Archive policy. |

## Relationships

- A User may have one or more Role contexts.
- A User may be associated with a Teacher, Student, Parent, Teacher Staff, or Super Admin context.
- User login events are recorded in the Audit Log.

## Business Rules

- Duplicate Student accounts are not allowed.
- Parent access is read-only everywhere.
- Teacher Staff actions must be attributed to the Teacher Staff user.
- No hard delete exists for User records.

## Notes

User identity is global. Role-specific access is controlled separately through Role, Permission, and contextual relationships.

# 2. Role

## Entity Name

Role

## Description

Represents one of the confirmed Version 1 user roles.

## Purpose

To classify the access context of a User.

## Attributes

| Attribute | Data Type | Required / Optional | Default Value | Validation Rules |
|---|---|---|---|---|
| Role Identifier | Identifier | Required | Generated by system | Must be unique. |
| Role Name | Enum | Required | None | Must be one of: Super Admin, Teacher, Teacher Staff, Student, Parent. |
| Role Scope | Enum | Required | None | Must match role boundary: Platform, Teacher Workspace, Student Account, or Parent Linked Students. |
| Description | Text | Optional | None | Must describe role responsibility without adding unconfirmed permissions. |
| Archived State | Archive State | Required | Active | Must follow Archive policy. |

## Relationships

- A Role is assigned to a User in a specific context.
- Teacher Staff Role is scoped to the creating Teacher Workspace.
- Parent Role is scoped to linked Students.

## Business Rules

- Version 1 has exactly five roles: Super Admin, Teacher, Teacher Staff, Student, Parent.
- Platform staff roles such as Support, Sales, and Accountant are out of scope for Version 1.

## Notes

Role does not by itself grant all access. Access must also pass contextual authorization and Permission rules.

Permission

## Purpose

To support role-based and custom permission checks without violating Teacher Workspace isolation.

## Attributes

| Attribute | Data Type | Required / Optional | Default Value | Validation Rules |
|---|---|---|---|---|

## Relationships

# 4. Teacher

## Entity Name

Teacher

## Description

Represents a paying customer who operates one isolated Teacher Workspace.

## Purpose

To identify the owner of a Teacher Workspace and the payer of the Platform Subscription under Flow A.

## Attributes

| Attribute | Data Type | Required / Optional | Default Value | Validation Rules |
|---|---|---|---|---|
| Teacher Identifier | Identifier | Required | Generated by system | Must be unique. |
| User Reference | Reference | Required | None | Must reference a valid User. |
| Teacher Workspace Reference | Reference | Required | None | Must reference the Teacher's own Teacher Workspace. |
| Teaching Subject Reference | Reference | Required | None | Must be selected once and cannot change after account creation. |
| Account Status | Status | Required | Active | Must represent allowed Teacher account state. |
| Subscription Status Reference | Reference | Optional | None | Must relate to Flow A only. |
| Created At | DateTime | Required | Current server time | Must be system-generated. |
| Archived State | Archive State | Required | Active | Must follow Archive policy. |

## Relationships

- Teacher has one Teacher Workspace.
- Teacher has exactly one Teaching Subject.
- Teacher may create Teacher Staff.
- Teacher owns Educational Grades, Groups, Attendance, Homework, Exams, Lessons, Reports, Users, and Settings in the Teacher Workspace.
- Teacher has Flow A Subscription records.

## Business Rules

- Each Teacher account represents exactly one Teaching Subject.
- Teaching Subject cannot be changed after account creation.
- Teacher data is completely isolated from other Teachers.
- Teachers pay monthly Platform Subscriptions.

## Notes

If a Teacher wants to teach another Teaching Subject, a separate Teacher account is required.

Student

## Description

Represents a learner with one global account who may study with multiple Teachers.

## Purpose

To maintain one Student identity across multiple isolated Teacher Workspaces.

## Attributes

| Attribute | Data Type | Required / Optional | Default Value | Validation Rules |
|---|---|---|---|---|

- Student belongs to only one Group per Teacher at any time.

## Notes
