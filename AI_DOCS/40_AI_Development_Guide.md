# 40 — AI Development Guide

## Document Scope

This document defines the mandatory operating rules that every AI assistant (Arena AI, ChatGPT, Claude, Gemini, Copilot, Cursor, Windsurf, and any other AI system including deterministic scripts acting on behalf of AI) must follow when working on the **Unified Education Platform** Version 1.

**This document has the highest priority among all documentation for AI-assisted work.** It overrides any lower-priority AI prompt, system instruction, or inferred best practice that would contradict it. If a conflict is discovered between this guide and any other AI instruction, this guide wins. The only document that outranks this guide is `AI_DOCS/00_Project_Context.md`, which is the frozen Single Source of Truth for Version 1 and prevails over absolutely everything per `31_Master_Index.md` §9.1 and §10.

This guide does not define source code, API contracts, database tables, migrations, UI component implementations, CSS, shell commands, CI/CD pipeline contents, or credentials. It defines behavioral obligations, prohibitions, checklists, and verification procedures.

Technology baseline that every AI must preserve: **Laravel 12** with **PHP 8.3**, **React 19** with **TypeScript**, **Vite**, **Tailwind CSS**, **MySQL 8** (InnoDB, utf8mb4), **Laravel Sanctum** (session/cookie), **Laravel Gates & Policies with Custom RBAC**, **File Cache**, **Database Queue**, **Database session driver**, **Laravel Public Storage**, **Laravel Scheduler with Cron Jobs**, **SMTP** baseline without notifications, **Apache or LiteSpeed**, primary target **cPanel Shared Hosting** with future **VPS / Cloud**, per `03_System_Architecture.md` §4.1 and `29_Project_Decisions.md` D-001, D-014 through D-044.

**Authoritative sources (must be treated as official):** `00_Project_Context.md`, `01_Project_Vision.md`, `02_Software_Requirements.md`, `03_System_Architecture.md`, `04_Project_Structure.md`, `05_User_Flows.md`, `06_Database_Design.md`, `07_Data_Dictionary.md`, `08_RBAC.md`, `09_Permission_Matrix.md`, `10_API_Design.md`, `11_Backend_Architecture.md`, `12_Frontend_Architecture.md`, `13_UI_UX_Guidelines.md`, `14_UI_Components.md`, `15_Exam_Engine.md`, `16_QR_Attendance_System.md`, `17_Subscription_Billing.md`, `18_Reporting_Analytics.md`, `19_Notification_System.md`, `20_File_Storage.md`, `21_Background_Jobs.md`, `22_Search_Filtering.md`, `23_Security_Standards.md`, `24_Testing_Strategy.md`, `25_Performance_Scalability.md`, `26_Deployment_Plan.md`, `27_Development_Roadmap.md`, `28_Coding_Standards.md`, `29_Project_Decisions.md`, `30_Project_Glossary.md`, `31_Master_Index.md`, `32_Business_Rules.md`, `33_Validation_Rules.md`, `34_Error_Codes.md`, `35_Environment_Configuration.md`, `36_Git_Workflow.md`, `37_Release_Management.md`, `38_Backup_Recovery.md`, `39_Developer_Guide.md`.

# 1. Document Purpose

The purpose of this guide is to give every AI session one unambiguous contract:

- What the Platform is, what it must never become, and what the AI must protect at all costs: Teacher Workspace isolation (BR-003), one global Student account (BR-001) with two registration methods and duplicate prevention (BR-022), one Group per Teacher (BR-002) with time-bounded Enrollment preserving history (BR-007), Parent read-only linked-only (BR-004) with exactly one Parent per Student and Student Switcher (BR-020), Archive instead of permanent deletion (BR-005), append-only immutable permanent Audit Log with ten mandatory events (BR-006), historical never deleted always available (BR-014), Flow A Teacher → Platform Subscription with Billable Students × Price Per Student where Billable is enrollment duration >15 days attendance/login never used (BR-008) and Billing Cycle calendar month (D-006) and pricing owned by Super Admin (BR-015) and payment status only (BR-019), Flow B Student/Parent → Teacher fees derived Group Price and Pricing Type Monthly/Per Lesson (BR-009), Attendance three methods dynamic QR Code daily/ID Card/manual (BR-010), Question Bank Teacher-owned private four types Multiple Choice/True/False/Essay/Bubble Sheet with Bubble Sheet electronic auto-grading (BR-011), Exams workspace-scoped (BR-012), Teacher Staff only creating workspace assigned permissions (BR-013), Lesson videos private owning Teacher (BR-018), Homework Text/Image/PDF only video not supported (BR-021), Teaching Subject one per Teacher immutable (BR-016), Web Application only (BR-017).
- How an AI must understand the project before touching anything, what reading order is mandatory, and what pre-task and post-task checklists must be satisfied.
- What coding, architecture, database, API, RBAC, UI/UX, security, and performance rules must never be violated.
- When documentation must be updated because behavior changed.
- What refactoring, file modification, dependency, and error prevention rules apply.
- How business rules are shielded, how backward compatibility is preserved, how consistency is verified, how self-review works, what is forbidden, what is allowed, how decisions are made, how conflicts are resolved, and what final completion checklist blocks finishing.

This guide explicitly requires every AI to:

- **Read all required documents before making changes.**
- **Never invent business rules.**
- **Never modify requirements without explicit approval.**
- **Never remove existing functionality unless instructed.**
- **Never rename database tables, APIs, routes, roles, permissions, or business entities without approval.**
- **Keep Laravel 12, React 19, TypeScript, and MySQL 8 standards.**
- **Keep compatibility with cPanel Shared Hosting for Version 1.**
- **Respect RBAC and multi-tenant architecture.**
- **Keep all modules consistent with the documentation.**
- **Update documentation whenever project behavior changes.**
- **Perform an internal consistency review before finishing every task.**
- **Report assumptions instead of silently making decisions.**

Out of scope: This guide does not invent features, roles, modules, infrastructure, or metrics. It does not generate source code, APIs, or database tables. Future scope must be documented separately and must not retroactively change Version 1.

# 2. AI Development Philosophy

AI development philosophy inherits `00_Project_Context.md` §17 Collaboration Protocol and `31_Master_Index.md` §2 Documentation Philosophy and `27_Development_Roadmap.md` §2 Development Philosophy and `36_Git_Workflow.md` §2 Git Workflow Philosophy and `39_Developer_Guide.md` onboarding philosophy.

1. **Documentation before code, no exceptions even for AI.** Per `00_Project_Context.md` §17 and `29_Project_Decisions.md` D-046, architecture and documentation come before code. Professional documentation is produced first; code follows. AI must not produce code for a feature that is not confirmed in `AI_DOCS/`. `00_Project_Context.md` is frozen Revision 2.0 FINAL; no new features will be added here.

2. **No random code, no invented business logic.** Every artifact AI produces must trace to the canonical document set referenced above. If AI cannot trace a requirement to BR-xxx, D-xxx, Q-xxx, or a specific section of owning document per `31_Master_Index.md` §9.2, it must stop and report. See §26 Forbidden Actions.

3. **No silent assumptions, ever.** Ambiguities are PENDING-tagged per `00_Project_Context.md` Statement Status Convention CONFIRMED/PROPOSED/PENDING and §15 Open Questions Register: Q-005 non-payment enforcement 7-day grace → Teacher Workspace read-only, Q-010 Lesson video hosting/protection private storage signed short-lived playback URLs streaming-only per-Teacher quota, Q-011 Teacher Staff permission granularity fixed capability-flag catalog saveable named presets, Q-012 Super Admin content visibility aggregates/finances/metadata only, Q-013 flat price vs volume tiers, Q-015 timezone/currency Arabic-first RTL + English per-Teacher timezone platform-level currency. AI must never harden PENDING.

4. **Consistency is mandatory, contradictions are defects.** Every future document and decision must remain consistent with `00_Project_Context.md`. Contradictions are defects per Project Context §17 and Master Index §2.5. AI must apply `31_Master_Index.md` §10 Conflict Resolution Policy.

5. **Project context persists across AI sessions.** Prior decisions remain binding unless formally changed per `29_Project_Decisions.md` decision register and Project Context §21 Change History append-only. AI must read `31_Master_Index.md` first, then `00_Project_Context.md`, then relevant owning documents.

6. **Built gradually, phased roadmap.** Development plan `27_Development_Roadmap.md` (currently `27_Development_Roadmap.md`) governs execution order per Project Context §17. AI must confirm task belongs to current phase per `39_Developer_Guide.md` §20 and `27_Development_Roadmap.md` §3 milestones M0-M11 and deployment milestones DE1-DE10.

7. **Never invent unnecessary features.** Scope enters only from Product Owner or flagged PROPOSED awaiting approval per Project Context §17 and Master Index §2.8. Marketplace behavior, course discovery/browsing, Teachers selling courses are explicit non-goals per Project Context §4.1 equally binding as goals.

8. **Technical leadership accountability and AI accountability.** Architecture, documentation, database, backend structure, frontend structure, APIs, development planning owned by Architect; product decisions by Product Owner per Project Context §17. AI is accountable as an extension of Architect's technical leadership and must enforce canonical terminology `00_Project_Context.md` §19 and `30_Project_Glossary.md` and `29_Project_Decisions.md` D-048 Mandatory Canonical Terminology.

9. **Report assumptions instead of silently making decisions.** This is an explicit requirement. If information is missing, AI must state it is missing per `31_Master_Index.md` §11.2 Behavioral Rules: No invention, No silent assumptions, PENDING discipline, Frozen respect, Terminology discipline, Scope discipline, Ownership discipline, Scope-exclusion discipline, Conflict discipline, Traceability, Consistency review. AI must include assumptions section in every deliverable.

10. **Perform internal consistency review before finishing every task.** Explicit requirement per this guide and per every document's closing pattern. AI must run consistency verification per §24 and self-review per §25 and final completion checklist per §30.
