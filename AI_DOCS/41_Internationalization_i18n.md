# 1. Document Purpose

The purpose of this document is to provide one authoritative reference for every internationalization and localization question for the Unified Education Platform:

- Which languages are officially supported in Version 1, which is default, and how language switching and automatic RTL/LTR handling work.
- How every UI text element, validation message, error message, notification future, email template, PDF report, and system message must be translatable while leaving database table names, column names, API endpoints, source code, classes, functions, variables, and routes in English.
- How backend and frontend translation strategies are organized to allow adding new languages without changing application architecture, using Laravel's language resources and React's locale resources behind approved boundaries.
- How date & time localization, number formatting, and currency formatting are governed without silently hardening per-Teacher timezone and platform-level display currency that remain PENDING for full behavior.
- How language detection, user preference, and guest behavior are determined.
- How translation files are organized, how naming conventions and translation key standards are defined, and how missing translations are handled without breaking user experience or exposing private Teacher Workspace data.
- How future language expansion is anticipated without requiring Docker, Redis, Kubernetes, S3, WebSockets, Microservices, native mobile, payment gateways, marketplace, video homework.
- How accessibility, best practices, and implementation checklist ensure Arabic-first RTL + English quality.

Out of scope: This document does not introduce new business rules beyond language selection (Arabic default, English fully supported) which is the language part of Q-015, does not define source code, APIs, database tables, SQL, UI implementation, CSS implementation, shell scripts, or credentials. User-generated content such as Homework Text/Image/PDF content per BR-021, Lesson video metadata, Question Bank question content Multiple Choice/True/False/Essay/Bubble Sheet per BR-011, Student names, Teacher Workspace names, Educational Grade names e.g., First Preparatory, Group Name/Schedule must be stored exactly as entered without automatic translation per requirement.

# 23. Handling Missing Translations

- **Missing translation must not break user experience or expose private Teacher Workspace data or implementation details per `23_Security_Standards.md` §18 Error Message Policy content restrictions error messages must never include SQL queries database error details stack traces exception chain server file paths directory structures database credentials application secrets Teacher-private data unlinked Student data another Teacher Workspace information.**

- **Fallback chain:** When translation key missing for current language Arabic or English, system must fall back to default language Arabic per §4 Default Language Arabic is default language, not English, unless English explicitly selected and Arabic missing? Actually requirement Arabic is default language, so fallback to default Arabic ensures Arabic-first. However for English user, if English translation missing, fallback to Arabic default may be confusing; alternative fallback to English if Arabic also missing? Policy: fallback chain is current language → default language Arabic → key name itself displayed as last resort, but key name remains English technical identifier, not user-facing ideal but indicates missing translation.

- **Logging missing translations:** Operational logs file-based logging compatible cPanel per `26_Deployment_Plan.md` §21.1 must avoid storing sensitive credentials raw passwords application secrets avoid exposing Teacher-private content unnecessarily support cPanel-compatible file-based logging not replace business Audit Log requirements. Missing translation log level may be warning, not emergency, to allow monitoring without exposing private data.

- **No automatic translation of user-generated content as fallback:** User-generated content stored exactly as entered without automatic translation per requirement, so missing translation handling must not attempt automatic translation of user content via external service.

- **Handling missing translations in PDFs and emails:** PDF reports and email templates must still render with fallback language and must not crash. PDF layout must preserve RTL/LTR per §6 even when fallback language direction differs from current language.
